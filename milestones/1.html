Architecture briefing · Milestone 001

How 24x7ai works

A universal agent fleet controller that turns a source of product ideas into Git repositories, runs coding agents to build MVPs, and supervises ongoing improvements through persistent project daemons.

01 · Big picture

One coordinator, interchangeable coding agents

The core owns orchestration, persistence, Git operations, scheduling, and logs. Agent adapters provide a common interface to external coding tools, so the pipeline does not depend on one particular agent CLI.

INPUT

Ideas & configuration

Ideas arrive from a local CSV, CSV URL, or Google Sheets. Application settings come from .24x7ai.config.json, with selected environment overrides.

CONTROL

TypeScript core

The pipeline selects work, adapters invoke agents, SQLite records outcomes, and locks prevent overlapping execution.

OUTPUT

Working repositories

Each idea gets a project directory, templates, a Git dev branch, commits, status metadata, and optional GitHub synchronization.

02 · Initial build

The serial MVP pipeline

src/core/pipeline.ts handles one eligible project at a time under a master lock. Completed projects remain in SQLite; incomplete projects are selected first.

Agent contract

Every adapter supports detection, invocation, and status parsing. Invocation receives the project directory, prompt, timeout, environment, and output callbacks. It returns exit code, duration, commits, changed files, output, and errors.

src/adapters/base.ts · src/adapters/registry.ts

Completion handshake

The agent maintains .agent-status.json. When mvp_complete is true, the pipeline marks the project complete so ongoing daemon work can take over.

03 · Continuous improvement

Scheduled project daemons

src/core/daemon-manager.ts supervises active projects. Due projects run in bounded parallel batches, while each repository has its own lock.

BEFORE

Eligibility & safety

Skip paused, stuck, locked, or backed-off projects. Scheduling determines which active daemons are due.

DURING

One useful improvement

Fetch a labeled GitHub issue when available, construct an improvement prompt, invoke the selected adapter, and record the run.

AFTER

Commit or back off

Successful work is committed and optionally pushed or submitted as a PR. Failures update error state and schedule exponential backoff.

Stuck detection: src/core/stuck-detector.ts evaluates repeated no-change runs, failures, and timeout-related state so problematic daemons can be quarantined rather than looping indefinitely.

05 · Milestone 001 addition

Direct Otari chat integration

The new reusable provider exposes chat({ role, messages }). It is intentionally separate from the full agent runtime and from the existing adapter environment gateway.

New

Direct provider

Reads logical model roles from config/models.json, maps kimi-k3.1-pro to together:moonshotai/kimi-k3.1-pro, and posts messages to Otari.

Gateway environment

Resilience

30-second default timeout; retries for network errors, timeouts, 408, 425, 429, and 5xx; exponential backoff and Retry-After support.

Security

Credentials are read only from the environment. Request bodies, sensitive headers, API keys, and response error bodies are not logged.

Observability

Valid token usage is logged with role, model, prompt tokens, completion tokens, and total tokens. Malformed success responses produce explicit errors.

Current role configuration: architect, builder, and tester all select Kimi K3.1 Pro. The configuration also contains a triage role using Llama, which the Kimi-specific provider currently rejects as unsupported.
06 · Operational model

Persistent state and operator controls

SQLite records

Projects store source ideas, slugs, completion, and activation. Agent runs store prompts, timing, exit codes, commit/file counts, and errors. Daemon state stores scheduling, status, consecutive failures/no-change counts, and backoff.

src/state/models.ts · src/state/db.ts · src/state/queries.ts

Primary commands

init configures a fleet; run executes MVP work; supervise runs due daemons; fleet opens the TUI; status reports state; adapter inspects agents; cron installs automation.

Also: logs · set-ideas · doctor · config · clean · backup · restore · export
