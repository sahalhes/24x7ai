# Task 001: 24x7ai Otari Gateway Integration

You are the lead developer working on 24x7ai.

## Objective
Implement the first working Otari AI Gateway integration using Kimi K3.1 Pro as the primary model.

## Existing configuration
`config/models.json`

Logical roles:
- architect
- builder
- tester

All three use `kimi-k3.1-pro`.

## Otari API
Base URL:
`https://otari.ai/api/v1`

Endpoint:
`POST /chat/completions`

Authentication:
`Otari-Key: $OTARI_API_KEY`

Model ID:
`together:moonshotai/kimi-k3.1-pro`

## Requirements

1. Inspect the existing repository and understand its architecture.
2. Read `config/models.json`.
3. Implement a reusable TypeScript Otari provider adapter.
4. Read API credentials exclusively from environment variables.
5. Support configurable model selection by logical agent role.
6. Support messages, system prompts, response parsing and error handling.
7. Add request timeouts and sensible retry handling.
8. Log token usage when the API returns it.
9. Never log API keys or sensitive request headers.
10. Add unit tests using mocked HTTP responses.

## Suggested interface

`src/providers/otari.ts`

Expose a reusable function:

`chat({ role, messages })`

It should resolve the model from `config/models.json` and send the request to Otari.

## Constraints
- Preserve the existing project architecture.
- Do not introduce unnecessary dependencies.
- Do not hardcode credentials.
- Do not implement the entire agent runtime yet.
- Do not overwrite unrelated files.

## Acceptance criteria

- TypeScript compiles.
- Tests pass.
- A real API smoke test can successfully call Kimi through Otari.
- API key is never exposed in logs.

First report your repository findings and proposed file changes. Wait for approval before implementing.
