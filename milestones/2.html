02 · State machine

Every transition is explicit and validated

RunLifecycle rejects illegal transitions. Failed and timed-out attempts may return to queued only while retries remain. Completed and cancelled runs are terminal; exhausted failures and timeouts remain in their respective states.

stateDiagram-v2
  [*] --> idle: run record created
  idle --> queued: dispatched
  idle --> cancelled: cancellation
  queued --> running: worker available
  queued --> cancelled: cancel queued work
  running --> completed: structured result
  running --> failed: execution error
  running --> timed_out: attempt deadline
  running --> cancelled: abort signal
  failed --> queued: retries remaining
  timed_out --> queued: retries remaining
  completed --> [*]
  failed --> [*]: retries exhausted
  timed_out --> [*]: retries exhausted
  cancelled --> [*]

Attempt history

Each attempt records its number, start/end timestamps, final status, and sanitized error. A retry keeps the same run and correlation IDs.

Timeout & cancellation

Each attempt has its own abort controller and deadline. Cooperative agents receive an abort signal; Otari requests propagate it to fetch.

Cleanup

Timers and abort listeners are removed after every attempt. Terminal in-memory state is released while the durable SQLite record remains queryable.

03 · Request path

A durable run before any model request

sequenceDiagram
  autonumber
  participant App as Application
  participant Mgr as ExecutionManager
  participant DB as AgentRuntimeStore
  participant Queue as TaskDispatcher
  participant Agent as RoleAgent
  participant Otari as Otari provider

  App->>Mgr: dispatch(agentId, task, options)
  Mgr->>DB: Persist idle run, then queued
  Mgr->>Queue: Enqueue one run ID
  Queue-->>App: ExecutionHandle + result promise
  Queue->>Mgr: Start when capacity is available
  Mgr->>DB: running + attempt metadata
  Mgr->>Agent: run(task, run context + abort signal)
  Agent->>Otari: Resolved model + system/user messages
  alt Successful response
    Otari-->>Agent: Content + optional usage
    Agent-->>Mgr: Structured role-specific result
    Mgr->>DB: completed + result + timestamps
  else Failure or timeout with retries left
    Mgr->>DB: failed/timed_out attempt
    Mgr->>DB: queued, then running retry
  else Cancellation or retries exhausted
    Mgr->>DB: Terminal status + captured error
  end
No uncontrolled parallelism: the dispatcher starts only as many jobs as maxConcurrent allows. Queued shutdown work is cancelled, while running work may finish normally or be explicitly cancelled.
Recovery policy: queued records are safe to resume. A record left in running after restart is marked failed instead of replayed, avoiding duplicate side effects. Recovery is a startup operation, not distributed scheduling.
